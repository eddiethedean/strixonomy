# Migration: v0.28.0 → v0.28.1

v0.28.1 is a **patch** on the v0.28 line: Ontology Graph blank-canvas recovery on first open in VS Code webviews, plus a macOS stable e2e harness fix. See [CHANGELOG](https://github.com/eddiethedean/strixonomy/blob/main/CHANGELOG.md) and the v0.28 overview in [migration/v0.28.md](v0.28.md).

## What changed

### Ontology Graph blank canvas ([#442](https://github.com/eddiethedean/strixonomy/issues/442), [#443](https://github.com/eddiethedean/strixonomy/pull/443))

- Mount React Flow only after laid-out nodes exist
- Await `fitView` and confirm the React Flow pane has a real size before enabling `onlyRenderVisibleElements`
- Clear the flow instance when switching to list view
- Keep graph canvas height scoped to the panel (not global `#root`)

**Symptom this fixes:** Opening Graph from a class briefly flashes then shows an empty canvas (controls/minimap visible); List view still works; **Developer: Reload Webviews** recovered the canvas on v0.28.0.

### CI / tooling

- Bump `@vscode/test-electron` to 3.1.0 so macOS VS Code ≥1.110 e2e finds `Contents/MacOS/Code` instead of the old `Electron` path
- Clear broken `.vscode-test` downloads between e2e retries

## Breaking changes

None.

## Upgrade

1. Install Strixonomy **0.28.1** (Marketplace, Open VSX, or release VSIX).
2. Pin CLI/CI with `cargo install strixonomy-cli --locked --version 0.28.1` or the matching Linux release tarball.
3. No workspace config or ontology file migration is required.
